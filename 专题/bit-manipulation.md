## 0. 符号

请记住，`^`表示异或操作（XOR），`~`表示取反操作或否定操作（NOT）。

## 1. 基本运算

| 运算       | 运算逻辑 / 特征                                                          | 常见恒等式与技巧                                                  |
| ---------- | ------------------------------------------------------------------------ | ----------------------------------------------------------------- |
| 加法       | 逢二进一；<br>`a ^ b` 表示无进位和，`(a & b) << 1` 表示进位              | `a + b = (a ^ b) + ((a & b) << 1)`<br>`x + x = x << 1`            |
| 减法       | 转化为加法：`a - b = a + (-b)`，利用补码表示负数                         | `-b = ~b + 1`<br>`a - b = a + (~b + 1)`                           |
| 与 (`&`)   | 两位均为 1 才是 1；<br>常用于指定位置 0（位清零）与掩码提取              | `x & 0s = 0`<br>`x & 1s = x`<br>`x & x = x`<br>`x & ~x = 0`       |
| 或 (`\|`)  | 只要有一位为 1 即为 1；<br>常用于指定位置 1（位置位）与合并标志          | `x \| 0s = x`<br>`x \| 1s = 1s`<br>`x \| x = x`<br>`x \| ~x = 1s` |
| 异或 (`^`) | 两位不同为 1，相同为 0（不进位加法）；<br>常用于翻转位与消去偶数次相同数 | `x ^ 0s = x`<br>`x ^ 1s = ~x`<br>`x ^ x = 0`<br>`x ^ ~x = 1s`     |
| 非 (`~`)   | 按位取反，1 变为 0，0 变为 1                                             | `~0s = 1s`<br>`~1s = 0s`<br>`~(~x) = x`<br>`~x = -x - 1`          |

**关于减法的说明**：不够需要借位，被借位的1变成0，之后的0全都变成1，不过实际需要借位的那个位置在运算是用的是2而不是1。

## 2. 手工位操作示例

|             |              |                  |
| ----------- | ------------ | ---------------- |
| 0110 + 0010 | 0011 \* 0101 | 0110 + 0110      |
| 0011 + 0010 | 0011 \* 0011 | 0100 \* 0011     |
| 0110 - 0011 | 1101 >> 2    | 1101 ^ (~1101)   |
| 1000 - 0110 | 1101 ^ 0101  | 1011 & (~0 << 2) |

答案：

- 第1 行 (1000, 1111, 1100)；
- 第2 行 (0101, 1001, 1100)；
- 第3 行 (0011, 0011, 1111)；
- 第4 行 (0010, 1000, 1000)。

### 第三列问题的解决技巧

1. 0110 + 0110 相当于0110 × 2，也就是将0110 左移1 位，即0110<<1。

2. 0100 等于4，一个数与4 相乘，相当于将这个数左移2 位。于是，将0011 左移2 位得到1100。

   > 每乘以一个2就是左移一位

3. 逐个比特分解这一操作。一个比特与对它取反的值做异或操作，结果总是1。因此，a^(~a) 的结果是一串1。

4. ~0 的值就是一串1，所以~0 << 2 的结果为一串1 后面跟2 个0。将这个值与另外一个值进行“位与”操作，相当于将该值的最后2 位清零。

### 其他问题的解决技巧

#### 0011 \* 0101

计算 **`0011 * 0101`**（二进制乘法）有两种非常直观的方法：

##### 方法零：先用十进制快速验算

- `0011` 对应十进制的 **3**
- `0101` 对应十进制的 **5**
- $3 \times 5 = 15$，而十进制 15 转为 4 位二进制就是 **`1111`**。

##### 方法一：二进制竖式乘法（像十进制一样逐位相乘）

二进制乘法规则非常简单：**乘 1 就是原数，乘 0 就是 0**。按照位从右往左依次相乘并错位相加：

```text
       0 0 1 1   (被乘数 3)

    ×  0 1 0 1   (乘数 5)

    -----------

       0 0 1 1   <-- 0101 的第0位是 1，即 0011 × 1

     0 0 0 0     <-- 0101 的第1位是 0，即 0011 × 0 （左移1位）

   0 0 1 1       <-- 0101 的第2位是 1，即 0011 × 1 （左移2位）

+ 0 0 0 0        <-- 0101 的第3位是 0，即 0011 × 0 （左移3位）

    -----------

       1 1 1 1   <-- 逐位相加：结果为 1111
```

##### 方法二：位运算分解（移位 + 加法）

在计算机底层的位运算中，**乘以乘数等于将被乘数按照乘数的 1 所在位置进行左移（`<<`）后再相加**：

1. 乘数 `0101` 的二进制位：
   - 第 2 位是 `1`（代表 $2^2 = 4$）
   - 第 0 位是 `1`（代表 $2^0 = 1$）
2. 将 `0011` 分别进行左移：
   - `0011 << 2` = `1100` （即 $3 \times 4 = 12$）
   - `0011 << 0` = `0011` （即 $3 \times 1 = 3$）
3. 将两项结果相加：
   - `1100 + 0011 = 1111` （即 $12 + 3 = 15$）

## 3. 位操作原理与技巧

下列表达式在位操作中很实用。不要一味死记硬背，而应思考这些等式何以成立。在下面的示例中，“1s”和“0s”分别表示一串 1 和一串 0。

```text
x ^ 0s = x    x & 0s = 0    x | 0s = x
x ^ 1s = ~x   x & 1s = x    x | 1s = 1s
x ^ x = 0     x & x = x     x | x = x
```

> 异或：相同的为0，不同的为1

要理解这些表达式的含义，你必须记住所有操作是按位进行的，某一位的运算结果不会影响其余位，也就是说，只要上述语句对某一位成立，则同样适用于一串位。

## 4. 二进制补码与负数

计算机通常以二进制补码的表示形式存储整数。 正数表示为自身，而负数表示为其绝对值的二进制补码（其符号位为1，表示负值）。N 位数（N 是数字的位数，不包括符号位）的二进制补码是相对于$2^N$ 的数字的补码。

换句话说，$-K$（$K$ 的负值）作为 $N$ 位数的二进制表达式为 $\text{concat}(1, 2^{N-1} - K)$。

> 这个就是分两步计算，然后拼接到一起。

另一种处理这种情况的方法是，可以反转正数表达中的每个数位，然后再加 1。3 表示为二进制数是 `011`。翻转所有数位得到 `100`，加 1 后得到 `101`，然后加上符号位（1）可以得到 `1101`。

在 4 位整数中，该过程可以表示如下：

| 正值 | 二进制 | 负值 | 二进制 |
| :--: | :----: | :--: | :----: |
|  7   | 0 111  |  -1  | 1 111  |
|  6   | 0 110  |  -2  | 1 110  |
|  5   | 0 101  |  -3  | 1 101  |
|  4   | 0 100  |  -4  | 1 100  |
|  3   | 0 011  |  -5  | 1 011  |
|  2   | 0 010  |  -6  | 1 010  |
|  1   | 0 001  |  -7  | 1 001  |
|  0   | 0 000  |      |        |

请注意，左侧与右侧整数的绝对值相加总等于 $2^3$（即 8）。同时，除了符号位以外，左侧与右侧的二进制值总是相等。

### 举例

我们以-3为例，如果用4位来表示：

- 3的表示：0 011
- -3的原码：1 011
- -3的补码：1 101

补码除了最前面的符号位是1之外，要看用几位数值位表示。比如用3位数值位表示，就是 $2^3 - 3 = 5$，也就是：1 101。

这也和用几位数表示有直接相关，比如同样是表示-3：

- 2 位数值位：1 01 ($2^2 - 3 = 1$)
- 3 位数值位：1 101 ($2^3 - 3 = 5$)
- 4 位数值位：1 1101 ($2^4 - 3 = 13$)
- 7 位数值位：1 1111101（$2^7 - 3 = 128 - 3 = 125$）

### 符号扩展（Sign Extension）

仔细观察：这里有一个非常神奇且重要的规律。

对比一下不同位数下的 $-3$：

- 3 位：`101`
- 4 位：`1101` （前面多了一个 `1`）
- 5 位：`11101` （前面又多了一个 `1`）
- 8 位：`11111101` （前面全是 `1`）

这就是计算机底层中非常著名的 **符号扩展（Sign Extension）**：

> 当要把一个有符号数扩展到更多的位数时：
>
> - **正数**：在左边（高位）全部补 **`0`**。
> - **负数**：在左边（高位）全部补 **`1`**。

#### 为什么高位补 `1` 值不会变？

以 4 位 `1101`（$-3$）变到 5 位 `11101` 为例：

- **4 位表示**：最高位权值是 $-2^3 = -8$，所以 $-8 + 4 + 0 + 1 = -3$。
- **5 位表示**：最高位权值是 $-2^4 = -16$，加上次高位的 $+2^3 = +8$。而 $-16 + 8 = -8$！ 后面的计算 $(-8) + 4 + 0 + 1$ 依然等于 **$-3$**！

### 直观理解：为什么补码要用 $8 - K$？

计算机设计补码的核心目的：**把减法变成加法（利用模运算）**。

想象一个只有 8 个刻度的环形钟表（0到7）：

- 往前拨 5 格（$+5$），和往后拨 3 格（$-3$），最后停在同一个位置！因为 $5 + 3 = 8$。
- 所以在模 8 的运算中，**减去 3 等价于加上 5**。

在二进制硬件电路里：

- `-3` 被存储为 `1 101`（符号位 $-8$ + 数值位 $+5 = -3$）。
- 这种方式让 CPU 只需要加法器就能同时处理正负数的加减法，无需专门设计减法器。

### 为什么要取反再加一

**最核心的原因之一正是为了解决“0”的问题！**

如果“只取反、不加 1”，计算机科学里叫**反码（Ones' Complement）**。而“取反 + 1”才叫**补码（Two's Complement）**。

为什么必须“+1”变成补码？主要有以下 **3 个极其关键的原因**：

#### 1. 消除“+0”和“-0”的歧义（正因为 0 的存在！）

如果不加 1（只按位取反）：

- $+0$ 的 4 位二进制是：`0000`
- 把 $+0$ 按位取反表示 $-0$，就会变成：**`1111`**

这就带来了严重后果：

1. **出现了两个 0**（`+0` 是 `0000`，`-0` 是 `1111`）。
2. 计算机电路每次判断 `x == 0` 时，必须同时检查 `0000` 和 `1111`，电路变复杂。
3. 4 位二进制原本能表示 $2^4 = 16$ 个不同的数，因为 0 占了两个位置，只能表示 15 个数，**浪费了一个编码位置**。

**加 1 之后（补码）：**

- `0000` 取反得 `1111`，**再加 1** 变成 `1 0000`。
- 因为只有 4 位，最左边的进位 `1` 溢出丢弃，结果变回了 **`0000`**！
- **`-0` 和 `+0` 的二进制表示完全重合为 `0000`**！彻底消除了 `-0`，且多出来的编码 `1000` 可以顺理成章地用来表示 **$-8$**。

#### 2. 数学上：从 $7 - K$ 凑齐到 $8 - K$

在 4 位整数中（3 位数值位）：

- 3 位数值位全为 1 时是 `111`（即十进制的 **7**，即 $2^3 - 1$）。
- **按位取反** 的本质是用全 1 的数去减，算出来的只是 **$7 - K$**。
- 但我们在模算术里（相当于 8 个刻度的钟表），需要的是 **$8 - K$**（即 $2^3 - K$）。
- 所以，**必须加上 1**，才能从 $7 - K$ 凑齐到 $8 - K$！

$$\text{按位取反} (7 - K) + 1 = 8 - K$$

#### 3. 让加法运算结果完美归零

以 $3 + (-3) = 0$ 为例：

- $+3$ 是 `0011`

**如果只取反不加1（反码 `1100`）：** $$\mathtt{0011 + 1100 = 1111} \quad (\text{结果是 } -0\text{，还需要人工加 1 才能变成 } 0000)$$

**取反且加1后（补码 `1101`）：** $$\mathtt{0011 + 1101 = 1,0000}$$ 溢出位 `1` 被硬件自然丢弃，剩下的 4 位直接就是 **`0000` (0)**！ 硬件加法器**不需要做任何特殊判断**，直接相加就能得到正确答案。

#### 总结

**“+1” 就是为了：**

1. 把 `-0` 挤回 `0000`，实现 **0 的唯一性**。
2. 填补全 1（$2^N - 1$）到 $2^N$ 之间**差的那个 1**。
3. 让 $A + (-A) = 0$ 在二进制加法电路中**自然溢出归零**。

## 5. 算术右移与逻辑右移

- **逻辑右移（`>>>`）**：不管正负，右移时最高位一律**补 0**。

- **算术右移（`>>`）**：右移时最高位**补充原数的符号位**（正数补 0，负数补 1），以维持正负号不变。

**移位终点的区别：**

- **逻辑右移**：对任何数（正数或负数）不断进行逻辑右移，最高位持续补 0，最终都会变为 **`0`**。

- **算术右移**：
  - **正数**：高位不断补 0，最终变为 **`0`**；
  - **负数**：高位不断补 1，最终所有二进制位都会变成全 1，即 **`-1`**。

> **为什么全 1 表示 -1？**
>
> 一串全 1 的二进制数在加 1 后，在定长加法电路中会高位溢出归零（`111...1 + 1 = 1000...0 -> 0`），因此全 1 表示 -1。
>
> 某个数全1，再加1等于0，那么这个数应该是-1。

## 6. 常见位操作：获取与设置数位

了解以下操作至关重要，但不要一味死记硬背，死记硬背会导致犯一些无法修复的错误。相反地，只需理解如何实现这些方法即可，从而确保在实现的过程中只是犯一些小错误。

### 6.1 获取数位 (Get Bit)

该方法将 1 左移 $i$ 位，得到形如 `00010000` 的值。接着，对这个值与 `num` 执行“**位与**”操作（AND），从而将 $i$ 位之外的所有位清零。最后，检查该结果是否为 0。不为 0 说明 $i$ 位为 1，否则，$i$ 位为 0。

```java
boolean getBit(int num, int i) {
    return ((num & (1 << i)) != 0);
}
```

### 6.2 设置数位 (Set Bit)

`setBit` 先将 1 左移 $i$ 位，得到形如 `00010000` 的值。接着，对这个值和 `num` 执行“**位或**”操作（OR），这样只会改变 $i$ 位的数值。该掩码 $i$ 位除外的位均为 0，故而不会影响 `num` 的其余位。

```java
int setBit(int num, int i) {
    return num | (1 << i);
}
```

### 6.3 清零数位 (Clear Bit)

该方法与 `setBit` 刚好相反。

#### 1. 清零第 $i$ 位

首先，将数字 `00010000` 取反进而得到类似于 `11101111` 的数字。接着，对该数字和 `num` 执行“**位与**”操作（AND）。这样只会清零 `num` 的第 $i$ 位，其余位则保持不变。

```java
int clearBit(int num, int i) {
    int mask = ~(1 << i);
    return num & mask;
}
```

#### 2. 清零最高位至第 $i$ 位（包括最高位和第 $i$ 位）

如果要清零最高位至第 $i$ 位所有的数位（包括最高位和第 $i$ 位），需要创建一个第 $i$ 位为 1（`1 << i`）的掩码。然后，将其减 1 并得到一串第一部分全为 0，第二部分全为 1 的数字。之后我们将目标数字与该掩码执行“位与”操作（AND），即得到只保留了最后 $i$ 位的数字。

```java
int clearBitsMSBthroughI(int num, int i) {
    int mask = (1 << i) - 1;
    return num & mask;
}
```

#### 3. 清零第 $i$ 位至第 0 位（包括第 $i$ 位和第 0 位）

如果要清零第 $i$ 位至第 0 位的所有的数位（包括第 $i$ 位和第 0 位），使用一串 1 构成的数字（即 `-1`）并将其左移 $i + 1$ 位，如此便得到一串第一部分全为 1，第二部分全为 0 的数字。

```java
int clearBitsIthrough0(int num, int i) {
    int mask = (-1 << (i + 1));
    return num & mask;
}
```

> -1就是一串全是1的数字

### 6.4 更新数位 (Update Bit)

将第 $i$ 位的值设置为 $v$，首先，用诸如 `11101111` 的掩码将 `num` 的第 $i$ 位清零。然后，将待写入的值 $v$（0 或 1）左移 $i$ 位，这样只会改变第 $i$ 位。最后，对这两个结果执行“位或”操作（OR），如此便能将 `num` 的第 $i$ 位更新为 $v$。

```java
int updateBit(int num, int i, boolean bitIs1) {
    int value = bitIs1 ? 1 : 0;
    int mask = ~(1 << i);
    return (num & mask) | (value << i);
}
```

## 7. 经典技巧

### 7.1 `n & (n - 1)` 精准消除最低位的 1

`n & (n - 1)` 是位运算中最经典高效的操作，核心功能是：**精准消除二进制表示中最右侧（最低位）的那个 1，同时保留其他高位不变**。

#### 原理拆解

- **$n - 1$ 的变化**：找到 $n$ 最右侧的第一个 1，这个 1 变成 0，而它右边的所有 0 全部变成 1（即“借位”）。
- **与 $n$ 执行按位与（`&`）**：
  - **该位右边**：$n$ 中原本全是 0，与 $n-1$ 变成的 1 相与，结果为 0。
  - **该位本身**：$n$ 中是 1，$n-1$ 中变成了 0，相与结果为 0。
  - **该位左边**：$n$ 与 $n-1$ 的高位完全一致，相与后原样保留。

#### 具体示例（以 $n = 12$ 为例）

```text
n         = 1 1 0 0  (十进制 12)
n - 1     = 1 0 1 1  (十进制 11)
--------------------
n & (n-1) = 1 0 0 0  (十进制 8，最右侧的 1 被消除了)
```

#### 高频应用场景

##### 1. 快速判断一个数是否是 2 的幂次方

2 的正整数次幂在二进制下有且仅有一个 1（如 $4 = 100_2, 8 = 1000_2$）。抹去唯一的一个 1 后如果变成 0，即为 2 的幂：

```java
boolean isPowerOfTwo(int n) {
    return n > 0 && (n & (n - 1)) == 0;
}
```

##### 2. 统计二进制中 1 的个数（汉明重量）

循环执行 `n = n & (n - 1)`，每消去一个 1 计数器加一，直到 `n == 0`。时间复杂度只与 1 的实际个数 $k$ 相关（$O(k)$），比逐位移位检查（$O(32)$）更高效：

```java
int countOnes(int n) {
    int count = 0;
    while (n != 0) {
        n &= (n - 1);
        count++;
    }
    return count;
}
```

##### 3. 计算两个整数相差多少位（汉明距离）

先用异或（`x ^ y`）找出差异位（二进制位相同为 0，不同为 1），再用 `n & (n - 1)` 统计结果中有多少个 1：

```java
int hammingDistance(int x, int y) {
    int xor = x ^ y; // 找出不同位（异或：相同为0，不同为1）
    int count = 0;
    while (xor != 0) {
        xor &= (xor - 1); // 精准消除最右侧的 1 并计数
        count++;
    }
    return count;
}
```

### 7.2 `n & -n`（Lowbit 运算）精准提取最低位的 1

`n & -n`（常称为 **Lowbit 运算**）的作用是：**提取二进制表示中最右侧（最低位）的那个 1 连同其后面的 0 所构成的数值**（即把除了最右边那个 1 之外的所有高位全部置零）。

例如，$n = 12$（二进制 `1100`），最右侧的 1 处于第 2 位（权值为 4），因此 $12 \ \& \ -12 = 4$（二进制 `0100`）。

#### 原理拆解（利用补码特性）

计算机中负数使用二进制补码表示，公式为：$-n = \sim n + 1$（按位取反再加 1）。

以 $n = 12$（四位二进制 `1100`）为例：

1. **按位取反 $\sim n$**：`1100` $\rightarrow$ `0011`
   - 最右侧原本的 1 变成了 0，而它右边的 0 全部变成了 1。
2. **末位加 1（得到 $-n$ 的补码）**：`0011 + 1` $\rightarrow$ `0100`
   - 加 1 触发了连续进位，使得原本最右侧的那个位置重新变回了 1，而它右边的位全变回了 0。
   - 最右侧 1 左边的所有高位依然保持着“取反”的状态。
3. **执行与运算 `n & -n`**：

```text
  n   = 1 1 0 0  (12)
 -n   = 0 1 0 0  (-12 的补码)
------------------
& 结果 = 0 1 0 0  (4)
```

- **最右侧 1 的左边**：$n$ 与 $-n$ 的高位完全相反，与运算结果全为 0。
- **最右侧 1 本身**：两边都是 1，与运算结果为 1。
- **最右侧 1 的右边**：两边都是 0，与运算结果全为 0。

#### 核心应用场景

##### 1. 树状数组（Fenwick Tree / Binary Indexed Tree）

树状数组的核心逻辑完全建立在 lowbit 之上，节点 $x$ 所管理的区间长度恰好就是 `lowbit(x)`：

- **单点更新时向上传递**：`x += x & -x`
- **前缀和查询时向左汇集**：`x -= x & -x`

##### 2. 配合状态压缩（Bitmask）逐个提取 1

在状压 DP 或集合遍历中，可以用 `n & -n` 快速拿到当前最小的元素，处理完毕后用 `n -= n & -n` 扣除该元素，从而高效遍历非零位：

```java
while (n != 0) {
    int lowestBit = n & -n; // 提取当前最低位的 1
    // ... 处理该元素
    n -= lowestBit;         // 消除该最低位的 1（等价于 n &= n - 1）
}
```

### 7.3 两大位运算神器对比

| 表达式            | 核心功能       | 效果示例 ($n = 12 = 1100_2$)       |
| :---------------- | :------------- | :--------------------------------- |
| **`n & (n - 1)`** | 抹去最低位的 1 | $1100 \rightarrow 1000$ (结果为 8) |
| **`n & -n`**      | 提取最低位的 1 | $1100 \rightarrow 0100$ (结果为 4) |
